# Client exposure audit

This Playwright harness runs the exposure implementation and element-selector
package from this checkout against an arbitrary client page. It does not
initialize Amplitude or send analytics events.

Build the repository first, then run:

```bash
pnpm build
pnpm exec playwright install chromium
pnpm harness:exposure -- --url https://example.com/products
```

The JSON report is written under `artifacts/client-exposure-audit/`. It answers:

- Which likely interactive elements are missing from the exposure allowlist?
- Does each generated selector uniquely resolve back to its element?
- Does a semantic component produce different selectors as the page scrolls or
  lazy-loads?
- Do generated-looking IDs or changing classes suggest an additional
  element-selector regex?
- Which selectors exposed at initial load, document scroll checkpoints, and
  overflow-container checkpoints?

## Options

```text
--headed                     Show the browser
--storage-state auth.json    Use a saved Playwright login
--viewport 390x844           Audit a device-sized viewport
--config audit-config.json   Override the allowlist or selector settings
--output report.json         Choose the report path
--no-scroll-containers       Skip overflow-container scenarios
--screenshot page.png        Save a full-page screenshot
```

Example configuration:

```json
{
  "exposureDuration": 150,
  "allowlist": [
    "a",
    "button",
    "input",
    "select",
    "textarea",
    "label",
    "[role=\"button\"]",
    "[data-amp-default-track]"
  ],
  "elementSelector": {
    "enabled": true,
    "shadowDomEnabled": true,
    "maxShadowDomDepth": 10
  }
}
```

`allowlist` replaces the harness default. Likewise,
`autogeneratedIdPatterns` and `unstableClassPatterns` are full replacements,
not additions. Copy the defaults from the report before adding a suggested
pattern.

## Reading recommendations

“Likely interactive” is intentionally broader than the SDK default. It includes
semantic controls plus common ARIA roles, `onclick`, and focusable elements.
The missing list is evidence for an allowlist change, not an automatic change:
review false positives such as focusable layout containers.

Regex suggestions are conservative and require at least two examples with a
shared prefix. Review them against authored IDs before rollout. The current v1
selector does not emit classes; unstable-class suggestions are included for
class-aware consumers and future selector strategies.

The harness never clicks controls, submits forms, or writes analytics. It does
scroll the document and up to ten visible overflow containers, which can trigger
normal lazy-loading behavior on the page.
