Element Selector: two SDK instances on one page

Two SDK instances are initialized with different API keys against the dev server's mock remote config (/api/remote-config/<apiKey>). Instance A gets autocapture.elementSelector.enabled: true, instance B gets false. One click on the probe button below is captured by both, and each instance's [Amplitude] Element Path is read from its own event pipeline.

The probe button's id contains a 4+ digit run, which the selector engine treats as autogenerated. So the enabled instance must drop the id and fall back to structure, while the disabled instance must keep emitting the legacy tag#id selector. The page also checks each instance's cached remote config still carries a boolean elementSelector.enabled, which is what breaks when one subscriber normalizes a delivery the whole page shares.
