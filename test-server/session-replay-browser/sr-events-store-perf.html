Events Store: size-check cost vs buffer size

Fills a session replay events store one event at a time and times each addEventToCurrentSequence call. Before the running-size cache, shouldSplitEventsList re-scanned every buffered string on every add, so the per-add cost grew with the buffer (up to ~17 ms at the 6 MB default cap). The legacy check is reproduced inline and installed on the same store so both runs differ only in the size check. The spinner stalls whenever the main thread is blocked.
