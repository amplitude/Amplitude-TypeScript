Microfrontend session replay — manual capture cases

Run pnpm dev from the repo root, open a case below with your project API key (VITE_AMPLITUDE_API_KEY or ?apiKey=), interact on parent and nested UI, then verify replays in Amplitude.

  • Case 01 — Same-origin iframe, SDK on parent only

    Typical shell + MFE iframe when only the host initializes session replay (default options).

  • Case 02 — Same-origin, SDK on parent and child

    Both frames load the SDK without crossOriginIframes (duplicate / non-merged recording).

  • Case 03 — Cross-origin coordinated (recommended setup)

    Parent and child with crossOriginIframes.enabled: true; baseline for correct nested capture.

  • Existing — Cross-origin iframe parent (CI reference)

    Original minimal parent/child pair used by Playwright e2e tests.

  • Case 04 — crossOrigin enabled on parent, no SDK in child

    Mirrors misconfiguration: coordinator on but child micro-app never loads the SDK.

  • Case 05 — Parent has crossOrigin; child SDK without flag

    Child loads session replay but omits crossOriginIframes.enabled.

  • Case 06 — Analytics + SR plugin on parent, bare iframe child

    Customer-style Browser SDK + plugin on shell; nested app has no Amplitude.

  • Case 07 — Iframe mounted after session replay starts

    Dynamic MFE load after init (MutationObserver / checkout timing).

  • Case 08 — Nested iframes (shell → MFE → widget)

    Three-level iframe tree with coordinated cross-origin on each document that runs the SDK.

  • Case 09 — Web component microfrontend (open shadow DOM)

    In-page MFE via custom element, not an iframe.

  • Case 10 — Sandboxed iframe without allow-same-origin

    Opaque child frame; often appears blank in parent-only replay.

  • Case 11 — coordinateChildren: false

    Parent does not send start signals; child SDK may never record in sync.

  • Case 12 — Script-mounted MFE (no iframe)

    Host loads micro-UI into a div (module federation–style mount without iframe).
