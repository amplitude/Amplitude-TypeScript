Settings and defaults

Setting Default Configurable? What it controls
Activity window
engagementThresholdMillis		 5 s Yes Time counts while the page is visible, focused, and within this window of an interaction. Idle gaps do not count.
Snapshot heartbeat
heartbeatIntervalMillis		 15 s Yes, SDK option Sends the cumulative page-view snapshot. It does not reset the inactivity deadline. Reach requested the cadence; customer control was not confirmed.
Page inactivity timeout
pageSessionTimeoutMillis		 3 min Yes One setting for both paths: the SDK finalizes after this long without qualifying activity. Each snapshot sends the same duration in the request's top-level timeout field, renewing the service fallback deadline from the last accepted heartbeat. If the SDK cannot deliver a final snapshot, the service finalizes the latest stored snapshot after that deadline. Heartbeats do not reset the SDK inactivity timer. The next interaction after SDK finalization starts a new logical page view.

Hidden tabs and unfocused windows pause engagement immediately. Page views retain their original timestamp, insert ID, and page-view ID across snapshots.

Service expiry and Event API ingestion are separate steps, so the timeout is not a guarantee of immediate ingestion. Local mode only acknowledges requests and does not simulate the service fallback.
