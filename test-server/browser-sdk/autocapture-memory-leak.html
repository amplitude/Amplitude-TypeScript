SDK-702: removed exposure elements

Create and remove three groups of buttons without navigating. Compare the affected published SDK with the local PR source.

  1. Run pnpm dev and open /browser-sdk/autocapture-memory-leak.html. Keep this tab in the foreground while running a cycle.
  2. Select an SDK, initialize it, then run a cycle. Each group contains 500 buttons by default: exposed for 600 ms, briefly visible for 30 ms, and never visible.
  3. After the cycle finishes, open Chrome DevTools → Memory and click Collect garbage (the trash-can icon). Then click Report counts or run ampLeak.report() in the Console.
  4. After GC, the fixed source should show zero reachable buttons in every group. The affected SDK should retain exposed and briefly visible buttons while collecting the never-visible control. Run more cycles to check growth without navigation.

Reload between SDK/settings comparisons. To inspect retainers, take a heap snapshot and search for amp-leak- button IDs. Avoid selecting, logging, or storing test elements in DevTools; DevTools itself can retain them.

No API key is needed. Remote config is disabled, and event uploads use an in-memory no-op transport. Published mode downloads the SDK from Amplitude's CDN.

Reachable counts alone do not prove a leak: force GC after the cycle. The page cannot normally request GC; the GC button works only in a browser launched with exposed window.gc.
