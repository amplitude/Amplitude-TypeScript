Contenteditable Element Text Test

This page reproduces a bug where clicking a contenteditable="true" rich-text editor (CKEditor 5) sends the text the user typed as [Amplitude] Element Text on [Amplitude] Element Clicked. The SDK's default exclusion is supposed to prevent this. It loads the script bundle from packages/analytics-browser/lib/scripts/amplitude-min.js (the amplitude-ts-script library), so run pnpm build first.

[contenteditable="true" i] is in DEFAULT_CSS_SELECTOR_ALLOWLIST, so a click anywhere inside the editor resolves to the editable root. DataExtractor.getText only masks descendants that have [contenteditable]. It never checks the clicked element itself, so the root's full innerText is captured.
